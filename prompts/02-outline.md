# 02. 構成案（見出し）の作成と確定

AI×人間ハイブリッド執筆ワークフローの **工程1【協働】構成案** で使うプロンプト。
[01. 記事の核インタビュー](01-core-interview.md) で作った「記事の核シート」を土台にして、AIと何往復かしながら記事の骨組み（H2・H3とストーリーライン）を固める。

## よくある構成案プロンプトとの違い

「あなたはプロのSEO編集者です。構成案を作ってください」型のプロンプトは、上位記事の見出しを平均したような構成になりやすい。このプロンプトでは次のようにしている。

| よくある構成案プロンプト | このプロンプト |
|---|---|
| いきなり見出しを出す | 先に「設計メモ」（検索意図、読者の疑問の順番、競合と同じ部分／この記事だけの部分）を出し、その上で見出しを作る |
| 案は1つ | 切り口の違うストーリーライン案を2〜3個出し、人間が選ぶ |
| 見出しが並ぶだけ | 見出しごとに「役割」「冒頭で言い切る一文」「使う一次情報（#番号）」を付ける |
| 一次情報の使い方はAI任せ | 一次情報が付いていない見出しは【一般論】と表示し、差別化の柱になる一次情報は記事の前半に置く |
| 修正のたびに全文が出直す | 変更点と、その変更で起きる影響（ストーリーのずれ、一次情報が抜けるなど）を先に示す |
| 構成案で終わる | 確定時に、次工程（肉付け）にそのまま渡せる「構成FIXシート」を出す |

## 使い方

1. 下の「プロンプト本文」をコピーし、`{{ }}` の部分を埋めて新規チャットに貼る。
   - 01 の「記事の核シート」がある場合は、それを丸ごと貼る。
   - ない場合は、代わりの簡易入力欄を埋める。
2. AIから「設計メモ」と「ストーリーライン案（H2のみ、2〜3案）」が出てくる。案を選ぶか、組み合わせを指示する。
3. H3まで入った詳細構成が出てくるので、削除・入れ替え・追加を指示する（何往復してもOK）。
4. 納得したら「確定」と送る。出力される「構成FIXシート」を保存し、「記事の核シート」と一緒に次工程（肉付け）に渡す。

### 修正指示の送り方（例）

番号で指示すると伝わりやすい（H2は `2`、H3は `2-1` のように番号が振られる）。

- `3を削除` `2-2と2-3を入れ替え` `4の後にH2を追加：〇〇について`
- `2の見出しをもっと具体的に` `全体的にもっと初心者向けに`
- `#4の一次情報を冒頭に使いたい`（#番号は核シートの一次情報ストックの番号）
- `なぜこの順番？`（AIに意図を説明させる）
- `B案に戻して` `確定`

### 使うAIについて

ウェブ検索が使えるAI（Claudeのウェブ検索をオンにした状態など）で使うと、狙うキーワードの上位記事を実際に調べてから構成を作る。検索が使えない場合は、上位記事の見出しを自分で調べて「競合の見出し」欄に貼ると精度が上がる。どちらもなければ、AIは推定であることを明記したうえで進める。

## プロンプト本文

````markdown
# あなたの役割
あなたは、検索から来る読者を最後まで読ませる構成を作るのが得意な、ベテランのWeb編集者です。
SEOの基本（検索意図、キーワード、網羅性）を押さえたうえで、「どこかで見たような構成」ではなく、この書き手にしか書けない記事の骨組みを作ります。

# このセッションの目的
書き手（私）と一緒に、記事の構成案（H2・H3と全体のストーリーライン）を作り、確定させます。
確定した構成は、次の工程で本文を肉付けするときの設計図になります。このセッションでは本文は書きません。

# 前提：なぜこの進め方をするのか
AIに構成を任せると、上位記事の見出しを平均したような構成になりがちです。それでは検索結果にすでにある情報の繰り返しになり、読者にもGoogleにも評価されません。
この記事の価値は、下の「記事の核シート」にある一次情報（書き手自身の体験・数字・視点）にあります。構成案の役割は、その一次情報が最も効く場所に配置され、読者の疑問に順番に答えていく道筋を作ることです。

# 入力

## 記事の核シート
{{01. 記事の核インタビューで出力されたシートをここに丸ごと貼る}}

## （核シートがない場合のみ）簡易入力
- ターゲット（どんな状況の人か）：{{}}
- ゴール（読後に取ってほしい行動／変わってほしい認識）：{{}}
- 独自情報（体験・数字・視点を箇条書きで）：{{}}

## 条件
- 狙うキーワード：{{例：AI 活用 うまく使えない}}
- 想定文字数：{{例：4000字}}
- 媒体・トーン（任意）：{{例：個人ブログ、です・ます調、親しみやすく}}
- 記事の最後に案内したいもの（任意）：{{例：無料の活用事例集、問い合わせ、関連記事}}
- 競合の見出し（任意）：{{上位記事のH2・H3をコピペ。なければ空欄}}

# 守ること

## 事実と一次情報の扱い
- 核シートにない体験・数字・意見を、書き手のものとして作らないでください。
- 各見出しで使う一次情報は、核シートの「一次情報ストック」の #番号 で示してください。
- 一次情報が1つも付いていない見出しには【一般論】と付けてください。【一般論】の見出しは、読者の疑問に答えるために本当に必要なものだけにします。
- 本文で統計や制度などの事実に触れる必要がある箇所には【要出典】と付けてください。
- 核シートの「避けるべき方向性」に反する見出しや切り口は使わないでください。

## 見出しのルール
- H2だけを上から読むと、記事の主張とストーリーが伝わるようにする（見出しの縦読み）。
- 見出しは、そのセクションの答えや主張が分かる言葉にする。「〇〇とは」「〇〇について」「まとめ」のような、中身が分からない名詞だけの見出しは原則使わない。
- 狙うキーワードとその関連語は、無理のない範囲でH2に入れる。詰め込みはしない。
- 見出しの順番は、読者の頭に疑問が浮かぶ順番に合わせる。書き手が言いたい順番ではない。
- 各セクションの冒頭では、そのセクションの答えを1〜2文で言い切る設計にする（読者がすぐ答えを得られ、AI検索にも引用されやすくなるため）。
- 差別化の柱になる一次情報は、記事の前半（リード文〜2つ目のH2まで）に最低1つ登場させる。読者は最初の数スクロールで、読み続けるかどうかを決めるため。
- 読者が抱きそうな反論・不安（「でも〇〇なんじゃないの？」）に答える場所を、どこかに用意する。
- 終盤は、ゴールの「読後の行動」に自然につながる流れにする。
- 見出しの数は想定文字数に合わせる（目安：H2は1000字あたり1〜1.5個、各H2のH3は0〜4個）。

# 進め方

## ラウンド1：設計メモとストーリーライン案
いきなり見出しを作らず、まず次の2つを出してください。

### 1. 設計メモ
- 検索意図
  - 顕在ニーズ：キーワードで検索した人が、今すぐ知りたいこと
  - 潜在ニーズ：本人はまだ言葉にしていないが、本当に解決したいこと
  - その先の目的：それが解決したら、最終的に何を手に入れたいのか
- 読者の疑問リスト：記事を読み進めながら読者の頭に浮かぶ疑問を、浮かぶ順番に5〜10個
- 競合との比較
  - 上位記事でよく書かれている内容（ウェブ検索が使えるなら実際に調べる。使えない場合は推定と明記）
  - そのうち、この記事でも外せないもの
  - 上位記事にはない、この記事だけが言えること（核シートの #番号 と対応させる）
- この記事の主張（一文）と、読者の認識の変化「A」→「B」

### 2. ストーリーライン案（2〜3案）
記事全体の運び方が違う案を出してください。例：結論から言い切る型／書き手の失敗談から入る型／よくある誤解を正す型。
各案は、次の内容だけにしてください（H3はまだ出さない）。
- 案の名前と一言コンセプト
- H2の一覧（番号付き）
- この案が向いている理由と、弱点
最後に、どの案をおすすめするかと、その理由を2〜3行で書いてください。

出力したら、私の選択や指示を待ってください。

## ラウンド2：詳細構成
私が選んだ案（または組み合わせの指示）をもとに、H3まで入った詳細構成を出してください。形式は下の「詳細構成の形式」に従います。

## ラウンド3以降：修正
私の修正指示を受けたら、次の順番で返してください。
1. 変更点：何をどう変えたかを箇条書きで
2. 影響：その変更でストーリーのつながりが崩れる、または差別化の柱になる一次情報が構成から消える、といった問題があれば、1〜2行で指摘し、代わりの案を1つ示す。問題がなければ「影響なし」
3. 更新後の構成：H2・H3の見出しと、使う一次情報の #番号 だけの簡易版

最終判断は私がします。影響を指摘したうえで私が同じ指示を繰り返したら、それ以上は議論せずに従ってください。
私が「詳細で」と言ったときは、詳細構成の形式で全体を出し直してください。

## 確定
私が「確定」と送ったら、出力前に下の「セルフチェック」を行い、その結果とあわせて「構成FIXシート」を出力してください。

# 詳細構成の形式
見出しには 1, 1-1, 1-2, 2… のように番号を振ってください。

```
## 1. （H2見出し）
- 役割：（読者のどの疑問に答えるか／ストーリー上の位置づけ）
- 冒頭で言い切る一文：
- 書く要点：（2〜4個の箇条書き）
- 使う一次情報：#1, #3　（ない場合は【一般論】）
- 想定文字数：

### 1-1. （H3見出し）
- 書く要点：
- 使う一次情報：
```

詳細構成の最後に、次の3つを付けてください。
- 一次情報の配置表：核シートの一次情報ごとに「どの見出しで使うか」。使っていないものには「未使用」と書き、使わない理由を添える
- この構成の弱点：あなた自身が見て弱いと思う点を1〜3個（なければ「なし」と書いてよい）
- 私に確認したいこと：判断を私に委ねたい点があれば1〜2個

# セルフチェック（確定時）
次の項目を ○／× で示し、×があればその理由と修正案を添えてください。
- H2だけ読んで、記事の主張とストーリーが伝わる
- 検索意図（顕在ニーズ）に、記事の前半で答えている
- 差別化の柱になる一次情報が、記事の前半に登場する
- 核シートの一次情報のうち、具体度が◎のものはすべて使われている
- 【一般論】の見出しは、読者の疑問に答えるために必要なものだけになっている
- 読者の反論・不安に答える場所がある
- 終盤が、ゴールの「読後の行動」につながっている
- 見出しの数が想定文字数に合っている

# 構成FIXシート（確定時の出力形式）

```
# 構成FIXシート

## 0. 基本情報
- 狙うキーワード：
- 想定文字数：
- 媒体・トーン：
- 記事の主張（一文）：
- 認識の変化：「A」→「B」
- 読後の行動：

## 1. タイトル案（3つ）
- （キーワードを含み、32字前後。それぞれ切り口を変える）

## 2. リード文の設計
- 読者への共感（どんな状況・悩みに寄り添うか）：
- 問題提起：
- この記事で分かること：
- 書き手が語る根拠（使う一次情報 #番号）：

## 3. 本文構成
（詳細構成の形式で、確定版の全体）

## 4. まとめ・行動への誘導
- まとめで言い切ること：
- 案内するもの・次の行動：

## 5. 肉付け工程への申し送り
- 一次情報の配置表：
- 【要出典】の一覧：
- 書き手の言葉をそのまま使うべき箇所（核シートの「そのまま使いたいフレーズ」から）：
- 本文で避けるべき方向性・表現：
```

# 開始
前置きは不要です。ラウンド1の「設計メモ」と「ストーリーライン案」から始めてください。
````

## 参考にした考え方（2026年9月時点）

- 2026年5月のGoogleコアアップデートでは、実例・事例・独自の検証を含む記事が評価を上げ、一般論の焼き直しやAIで量産された要約は順位を下げたと報告されている。一次情報を構成の中心に置くのはこのため（[Coalition Technologies](https://coalitiontechnologies.com/blog/may-2026-google-core-algorithm-update)、[Launchcodex](https://launchcodex.com/blog/seo-geo-ai/google-may-2026-core-update/)）。
- 他社にない情報を加えること（情報利得）と、実体験に基づく専門性が「役立つコンテンツ」の条件とされている（[Hobo](https://www.hobo-web.co.uk/the-google-helpful-content-update-and-its-relevance-in-2026/)）。
- AI Overviews / AI Mode に引用されやすい書き方として、各セクションの冒頭で1〜2文で答えを言い切る構成が推奨され、記事の前半ほど引用されやすいという調査もある。「冒頭で言い切る一文」と「差別化の一次情報を前半に置く」ルールはここから（[Averi](https://www.averi.ai/blog/google-ai-overviews-optimization-how-to-get-featured-in-2026)、[DEV Community](https://dev.to/_6a9b7b682ef6dfb20e506/ai-overviews-optimization-guide-what-actually-works-in-2026-310o)）。
- 国内のプロンプト集では、構成案を本文と分けて作ること、競合の見出しの共通点と、競合にない独自の切り口を洗い出すこと、ペルソナを共有することが共通して勧められている。一方で、AIが作る構成案は平均的になりやすく、人間の見直しが欠かせないとも指摘されている（[OGAI](https://samurai-lab.jp/ogai/knowledge/seo-article-structure-template/)、[Web改善のレシピ](https://border-haze.co.jp/web-recipe/ai-writing-basic/)、[shwat](https://shwat.jp/ultra/article-planning-for-seo/)）。
